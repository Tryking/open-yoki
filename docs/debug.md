# 调试手册：怎么调出一个像真人的数字人主播

[English](debug.en.md)

搭起来能播只是开始。观众说“一股 AI 味”“像客服”“怎么一晚上都在说这个”“情绪在哪里”，这份手册讲的就是这些毛病怎么找、怎么修、修完怎么确认。顺序按搭建的先后排：先能开播，再调性格、调嘴、调声音、调画面，然后每天体检，最后从真人主播身上学习惯。第 8 节是速查表。

配套工具都在 [tools/debug](../tools/debug/)，每个都能先用假数据离线自检（`sh tools/debug/selftest-all.sh`，不联网、不花钱）。

| [checkup](../tools/debug/checkup/) | 第 1、6 节：每日体检、回放某天的直播 |
| [capture](../tools/debug/capture/) | 第 2 节：看外壳到底给模型发了什么 |
| [heart-compare](../tools/debug/heart-compare/) | 第 2 节：心的新旧对比（在副本上重放） |
| [facts-align](../tools/debug/facts-align/) | 第 2、8 节：几张嘴的小抄是否一致 |
| [line-lint](../tools/debug/line-lint/) | 第 3 节：台词磨损、重复、免责话、语言跟随、冷场 |

## 0. 几条通用规矩

- **先看记录再动手。** 每场都留：她说的每一句（带时间、回的是谁）、收到的每条弹幕、心每一拍收到什么、写了什么。没有记录，只能凭感觉改，改完也说不清好没好。
- **一次只改一样。** 同时换模型又改人设，好了也不知道是哪个起的作用。
- **同一批输入做新旧对比。** 从真实记录里挑场景，旧版新版各跑一遍放在一起看。测试用副本，别污染她真的记忆，测试观众的名字要一眼能认出是测试。
- **写下数字。** “某个词一晚说了 76 次，改完 32 次”比“好多了”有用。离线对比好了，下一场真直播还要再看一次，线上常常冒出新问题（例如数字压下去了，换成某个词重复）。
- **像不像人，最后让人判断。** 找没参与开发的人读记录、盲选、盲听。不要拿模型打分代替，也不要拿开发者自己写的人设稿当成果：能算数的只有她直播时真说出口的话。
- **测试时把动钱的、往外发东西的都关掉。**

## 1. 先搭起来能开播

目标是一条最小链路先跑通：读弹幕 → 嘴出一句 → 配音 → 数字人出画面 → 推流到平台。心可以后接。搭建步骤见 [SETUP.md](../SETUP.md)，这里只讲跑通以后怎么查。

**怎么发现问题**

- **一段一段量延迟。** 弹幕进来到台词出来看服务器日志的时间戳，台词送出到数字人出声看数字人服务的回包时间，再加上读弹幕的轮询间隔和平台推流延迟。大致的量级：嘴 4–6 秒，数字人出声 2–3 秒，观众从打字到听到回答 10–15 秒。哪一段明显超出就查哪一段。
- **声画对不对得上。** 录一段推给平台的画面，找 5 处嘴明显张开的瞬间，对着声波看差多少，取平均。
- **画面卡不卡。** `python3 tools/debug/frame-check/framecheck.py fps 录像.mp4`，看每 20 秒里真正在动的帧数。
- **弹幕有没有重复、漏读。** 同一条弹幕被回了两遍，多半是读取时把界面上的按钮文字一起读进来了，内容一变就被当成新的。
- **开播、下播、断流。** 用体检工具的 `show` 检查回放一场：几点出第一帧、有没有提前断、最长多久没读到一条弹幕。

**怎么修（常见的几种）**

- **画面一卡一卡：** 推流页面按固定定时器（例如每秒 25 次）去截一个 24 帧的视频，说话时每 4–5 帧就会重复一帧。改成来一帧画一帧（浏览器的 `requestVideoFrameCallback`），推流帧率和数字人帧率一致。视频元素别放在屏幕外或隐藏，浏览器会停止绘制它，几乎全算丢帧。
- **嘴比声音晚：** 在推流页里把声音整体延后同样的时间（例如量出来嘴晚 0.1 秒，声音就延后 0.1 秒）。只改推流那一路，别动网页播放。
- **断流重连后一直掉帧：** 重连后检查帧率，低了就把画面源重新挂一次。
- **弹幕重复：** 去重键用“昵称 + 内容 + 短时间窗”，读取时滤掉界面按钮文字。

**怎么确认修好了**：frame-check 里低于阈值的窗口接近 0；5 处声画平均差在 0.05 秒以内；10 条测试弹幕全部回到、没有重复；体检回放这一场没有报错。

## 2. 调性格（人设、心）

先分清两样东西：**心**在后台常驻，决定她此刻心情怎样、在想什么、记人记事，把“此刻”写成一张便签；**嘴**是一个快模型，读便签和眼前的事件出台词。心不直接说话。

**怎么发现问题**

- **读心的记录。** 把一晚的“此刻”便签拿出来数：多少条是她自己的感受和念头，多少条是主持技巧和自我提醒（“先招呼住”“别冷场”“注意别说教”）。后者多，说明心变成了导演或者查错员，嘴念出来就是一股主持腔。
- **看心长不长进。** 一周里她的自我认识、看法、记人笔记有没有变化；日记是不是天天差不多；常来的观众有几个有笔记。
- **抓一次真实请求。** 用 [capture](../tools/debug/capture/) 起一个假接口，把心或嘴的接口地址临时指过去跑一拍，看真正发出去的 system 有多长、开头写的是什么、带了几个工具、温度和思考模式怎么设的。
- **让人读。** 把她一天的心里话和直播原话给一个没参与开发的人读，问一句“像不像一个人”。听到“一股 AI 味”时先别急着换模型。

**常见根子和修法**（按出现的频率排）

1. **外壳。** 心跑在编程 agent 一类的外壳里时，模型每一拍先读到“你是编程助手”和几万字的工具说明，人设只是最后追加的一段。这种情况下换哪家模型都是一个味。修法：直连模型接口，自己管会话，只给她几个读写自己家目录的小工具；或者用外壳提供的“整段替换 system”的方式，而不是“追加”。
2. **思考模式和温度。** 有的模型思考模式默认开，开着时温度等参数一律不生效。角色对话一般关掉思考，温度从 1.0 开始试。更高的温度在短测试里显得活泼，长对话后半段可能开始语句不通，要用长对话测。
3. **规矩太多。** 说明书越长、“不 / 别 / 禁止”越多，她说话越像念稿；禁词表会被当成提词器，规则过几轮就失效。修法：人设只写事实（她是谁、在哪、在乎什么、答应过的几条边界），说话方式靠真实对话示范。把“不许做什么”改成“她是什么样的人”。可以把说明书里“不 / 别”的个数当一个指标，改完数一下。
4. **替她写自我介绍。** 一段段地替她声明“我很在乎你”“这是真的”，越声明越像装的。真人不会这样介绍自己。少写“她是谁”，多喂她自己真发生的事：发过的帖、开播的数据、押过的预测和对错、遇到的人、刷到的消息。真实的小失误认一次、笑一笑就过去，可以变成她自己的梗；观众给她起的外号由心记下来，下次自己接住。
5. **底层没接上。** 心的会话几分钟就重开一次、新会话不读当天的日记，“此刻”便签被迫当成全部记忆；记人停了；查错占满了每一拍。这些不修，人设写得再好也留不住。修法：今晚发生的事单独一份文件，新会话开头带上当天日记；下播后固定一拍专门整理记人；查错挪到下播后做一次。
6. **免责话漏进嘴。** 心在便签里写“注意别喊单”，嘴就一晚上说几十次“我没喊单”。没人问的事，她自己先撇清，等于告诉观众“我在防着你”。修法：边界写成她自己答应过的事，只在真有人可能上当的时候当场说（例如有人发骗子链接：“这个别点，我替你们挡一下”）。

**温度从哪来**（研读材料的结论，写人设和看记录时对照）：她眼里有“这一个人”，不是“一条弹幕”；她有在乎的东西，也有会失去的东西；她是一个连着的故事，昨天说的今天还记得，说话算数。反过来就是工具人：看人只看风险、自己什么都不在乎、每一句都从零开始。

**必须诚实的地方**：被认真问就承认是数字人；不假装有自己没有的经历；共情守住“好像”（“想想都心慌”，不说“我完全懂你的痛”）；不许诺做不到的事（“我永远陪着你”）；不挽留、不制造依赖；有人流露出想伤害自己时，认真对待，诚实说自己是数字人、帮不了全部，请他联系身边的人或专业求助渠道。

**怎么验证**

- 用 [heart-compare](../tools/debug/heart-compare/) 从日志里挑 4 拍真实输入（开播中弹幕多、刚下播、白天一个人、想起某个人），旧设置和新设置各在副本上跑一遍。看三样：她回了什么；写了哪些文件、写成什么样；花了几秒。新版应该是：便签里她自己的感受多过主持技巧，记人的文件有更新，不替嘴写台词。
- 记数字：一场里免责话出现几次；便签里自我提醒几条；一周里看法和记人文件改了几次。
- 让人看：旧版、新版的记录混在一起给人读，不告诉哪份是新的。

**小抄要和心对齐。** 群里秒回、自动发帖、回推这些“别的嘴”往往各自带一份小抄。心记住了新事、或者你改了一个决定，小抄没跟上，她就会在群里说出和直播里相反的话。用 [facts-align](../tools/debug/facts-align/) 把关键事实列出来（该出现的说法、说反了的说法），每次改心或改决定后跑一遍；再写几个问题用 `--probe` 去问每条通道。部署前检查里也放一遍。

## 3. 调嘴（说话像真人、语言跟随、别重复）

**怎么发现问题**

- `node tools/debug/line-lint/lint.mjs 一场的记录.jsonl --md 报告.md`，先看“值得一看”那几条。
- 记几个数：一晚说了多少句、多少句是打招呼、说得最多的词和数、最长冷场多久、回话里有多少先叫了对方名字。
- 换模型之前跑 [model-blind](../tools/debug/model-blind/)：同一批场景、同一份人设，几家模型各说一句，打乱顺序让人凭“哪句像真人”选，选完才揭晓，同时给出平均几秒一句、花多少钱。
- 改人设、改提示之前之后跑 [mouth-compare](../tools/debug/mouth-compare/)，两边并排，下面附 line-lint 的数字。
- 站在观众的位置，从头读 30 句连着的话。

### 3.1 一股 AI 味、像客服

症状：“希望对你有帮助”“我理解你的感受”、每段话最后升华一下、动不动讲道理、每句都号召大家做点什么、拿“各位朋友”开头。

修法：嘴只读一页短的事实（她是谁、她在哪、答应过的几条边界）、心写的此刻便签，再加真人主播的原话当示范：按弹幕类型（夸、损、问是不是 AI、聊钱、闲聊、冷场、进场）各挑 5–7 句真人说过的话放在最后。事件只交代事实（“【弹幕】小林：你是不是AI”），不要再附一大段“你应该怎么回”。长规矩、字数要求、真人语录太多都会把她带回念稿。

验证：line-lint 里 `ai_tell`、`sermon`、`disclaimer` 为 0 或接近 0；盲比里新嘴赢；人读记录不再说“像客服”。

### 3.2 重复

几种重复要分开看：同一个开头或结尾；同一个口头禅；同一个数一晚上说几十次（比如盯着的某个价位）；同一个话题问一晚上（比如一道菜到处问人）。

修法，可以叠着用：

1. **最近几句放在用户消息的最后**，提示“开头、结尾、句式、口头禅都别跟上面重复”。放在 system 里效果差，模型会照抄自己最近的开头和收尾。
2. **出话前用代码检查一次**（line-lint 导出的 `repeatOf`）：和最近 3 句开头两个字一样、和最近几句结尾四个字一样、或者有连续五个字重合，就带着提示重写一次。只重写一次，不然延迟太长。
3. **说腻的数和词**（`wornTopics`）：最近 20 句里一个数出现 3 次、或者一个词出现 4 次，就算说腻了。冷场时换一个完全不同的新话题；回弹幕时提示别再提（`wornReply`，对方自己问到的不拦）。
4. **心里挂着的话题**（`wornNote`）：便签里“在想 / 今天想聊”那一行，她已经说过两次就从便签里拿掉，不然嘴每句都会去碰它。
5. **口头禅**：刚说过的口头禅下一句提示别用；示范句里同一个口头禅别占太多。

验证：同一批真实上下文重放，看那个数或词出现几次；下一场再跑 line-lint 看 `worn`。数字压下去以后常常换成某个词重复，一起看。

### 3.3 不接上下文

症状：只看眼前这一条弹幕，刚说过的事接不上。

修法：回弹幕、冷场时都带上“刚才直播间里”的最近 10 分钟：别人说了什么、她回了谁什么，按时间排，十几条就够。

验证：准备一串连续追问（“那刚才那个呢？”“你上一句说的是谁？”）跑一遍。

### 3.4 语言跟随

症状：别人用英文问，她用中文答。全中文的提示会把模型拉回中文。

修法：判断弹幕的语言（`langOf`），不是中文就在这条事件后面明确写“他用什么语言就只用那种语言回，一个中文字都不要”。用英文聊行情要提醒一句：英文习惯里涨是 green、跌是 red，和中文的红涨绿跌相反。

验证：line-lint 的 `language` 为 0；准备英文、日文、韩文、俄文、越南文各几条测试弹幕。

### 3.5 机械点名

症状：每句回话先叫一遍对方的名字；有人进场就念一遍 ID。被当成“一个数字”的感觉就从这里来。

修法：大部分回话提示不叫名字；进场不念 ID；老观众来了叫外号、提一件他的小事（“你上次说要戒合约，戒了没”）。

验证：line-lint 的“回话先叫名字”比例降到三成以下。

### 3.6 每句一样长

修法：长度按比例随机，短反应和长一点的碎碎念混着来；打招呼和道谢只给一句话的长度。

验证：line-lint 的长度离散度（spread）不要太低。

### 3.7 冷场

症状：没人打字时抱怨“没人理我”“就我一个”、数冷场了几分钟、硬讲笑话；或者干脆停很久不说话。

修法：明确告诉她“没人打字不等于没人看”，这类话别说；冷场时给她新素材：刷到的帖子、快讯、她自己今天的事、接着上一句补一个细节；也可以就是小声念叨手上正在干嘛（“这根……再等等看”）。控制自言自语的比例，太高了又会变成一晚上的抱怨。

验证：`quiet_complaint` 为 0；冷场超过 40 秒的次数和最长时长（line-lint 的 dead air）。

### 3.8 编了又收回

先分清两种“编”：玩笑、夸张、小故事、逗人，不算错，也不用收回；把没发生的事当真事说（没刷到的新闻、没开的单、编出来的数字），才是要管的。

常见的坑：心只收到她说出口的话，没收到她刚才刷到的原文，就把她真念过的新闻当成编的，让她当众收回道歉。修法：把“她刚刷到的：来源 + 原文”也喂给心；真编的记下来、以后别再提，不当众收回；只有会让人亏钱或上当的（空投、链接、喊单类）才当场说“别信”。

验证：一场里“说完又收回”的次数。

### 3.9 嘴说错了

症状：嘴把便签的格式字念出来、把便签里第二条“想：”也念了、把别人的事说成自己的、和便签对不上。

修法：便签用固定格式，嘴的提示只取需要的几行；解析要容错；每种出过的错写一条测试。

## 4. 调声音

**怎么发现问题**

- 人听。反馈多半是“像 AI”“情绪在哪里”“有点干”，说不清具体哪里。
- 量。[voice-audition](../tools/debug/voice-audition/) 的 `measure.mjs` 量三样：音高起伏（半音）、响度起伏（分贝）、快慢比（最快一段和最慢一段的语速比）。拿同一个人真实说话的录音一起量，差多少一目了然。平的合成声通常三项都明显低于真人。
- 盲听。`ear.mjs` 把同一句的几个版本打乱交给能听音频的模型，只听语气、从固定的情绪列表里选；该是“生气”的那条听不出生气，就是平。
- 字准。`words.mjs` 用语音转写查喊破音、哭腔以后字还在不在。
- 延迟。直播里每句请求时间的中位数要够短（例如 1–2 秒），换引擎前一起比。

**怎么修**

1. **台词写成脱口而出的样子。** 打断、重复、半句话、语气词（“嗯……”“哎哎哎”“呀”）、叠词、停顿。“干”多半是缺这些节奏语气词，加上以后听感变化最大。
2. **一句拆几段，每段单独给语气说明和快慢。** 合成后每段先拉到同一音量，再按计划加减分贝、接停顿；负的停顿表示抢着说、压在自己话尾上（`stitch.mjs`）。很多配音接口会把音量压平，起伏要自己放回去。
3. **复刻声音时挑参考音。** 同一个声音换不同的参考，出来的情绪差很多。让真人照着按情绪分段的台本录（激动、慌、生气、撒娇、委屈、笑场、嫌弃……），挑最有劲的几段拼成 35–55 秒当参考。录音里真人即兴加的段子，可以当成角色自己的口头梗。
4. **别指望一个情绪标签。** 只给“生气”标签，出来的往往情绪很稳。
5. **换引擎前三样一起比**：效果、延迟、价格。

要照实说的限制：分段以后字数多了，配音钱大约翻倍；真尖叫、真哭这类引擎可能做不出来；声音小的段落要看数字人的嘴型跟不跟得上。

**怎么验证**：三项数字往真人靠；盲听命中率上去；字准不低于 0.9；最后用 `reel.mjs` 做一条“旧版 → 新版”连播给人听，告诉他顺序，不要让人自己在一堆文件里找。

## 5. 调画面和脸

**怎么发现问题**

- 卡顿、声画：见第 1 节。
- **脸像不像。** `framecheck.py sheet 录像.mp4 --every 2 --ref 定妆照.png --crop ...`，每 2 秒一帧裁出脸，旁边放定妆照，用眼睛一格一格看。自动的相似度分数通过了也要看：出过分数通过、人一眼就看出脸变了的情况。
- **动作和表情。** 一晚上某个小表情用了多少次（动作标签在台词里时，line-lint 的 tags 能数出来）；动作和台词的情绪对不对得上；新动作有没有挡嘴、穿帮。

**怎么修**

- **脸：** 只认一张主脸当参考，所有新造型、新片段都对着它验。全身画面里脸小，最容易漂：把脸裁出来放大单独重画，再用带羽化遮罩的局部重绘贴回去。
- **动作：** 动作库按情绪分类，每类至少三四个可选，不然一个表情会用一整晚。新动作先标成“试用、只在不说话时用”，用真形象录一段逐帧验收，过了再放开。坐着播的角色，设计坐着能做的动作：手在脸旁或胸前、不挡嘴、不碰头饰。
- **大动作片段：** 几秒长的预制片段叠在画面上播，淡入淡出；触发条件写清楚（行情大涨大跌、收到礼物、有人关注）。

**怎么验证**：并排图每格都像；用得最多的那个表情占比低于 20%；新动作录像逐帧没有穿帮。

## 6. 每天体检

线上的问题常常是你自己先发现的：修好了，过两天又坏了。所以每天下播后自动查一遍，能修的先自己修，修不了才告诉你。

**查什么**（[checkup](../tools/debug/checkup/) 的检查项，按你的部署改配置）：主程序在不在；心多久没动；今晚几点开播、有没有提前断、读弹幕最长多久没读到一条；群里有人说话她接没接；发帖、回帖的通道在不在动；网站能不能打开；硬盘。你自己私有的部分（读弹幕用的浏览器登录还在不在、交易程序、另一台机器上的看门狗、私有面板）都写成 `command` 检查：一条命令，退出码 0 就算正常。

**自动修什么**：只修安全、能回退的，比如心卡住了就重启主程序；直播时段不动（`quiet_hours`）；修完再查一次，报告里写明恢复没有。

**怎么提醒**：没问题不打扰；有问题、或者自己修过了才发消息。报告每天一份存档。

**体检自己也要长**：每次线上出了体检没抓到的问题（例如读弹幕卡住了 26 分钟，开播检查却显示正常），就补一条检查项，再用 `--replay 那一天` 回放，确认这次能抓到。

**怎么验证**：`python3 selftest.py` 通过；拿出过事的那天回放，能报出来；连续几天没事时确实不发消息。

## 7. 从真人主播蒸馏习惯

目的是学真人怎么说话、怎么动，让角色有自己的样子，不是复刻某一个人。

**步骤**

1. **选人选片。** 选和你的角色气质接近、素材多的主播。每段截 2–3 分钟，覆盖不同场面：回求助、讲故事、冷场、要点赞或礼物、卡关。
2. **准备素材。** [distill-prep](../tools/debug/distill-prep/)：低清片段、每 2 秒一帧的编号拼图、音频和转写对齐。素材只放本机，不进仓库。
3. **说话层。** 一条一条记她实际怎么做，每条带原话和片段号。常见能学到的：
   - 先把弹幕念一遍再答，屋里的人都知道她在回谁；
   - 一句弹幕撑一整段：先下结论，再讲自己一件具体的真事（具体的人、具体的时间），最后回到结论；
   - 自嘲用真事，平平地说，不等人笑；
   - 毒舌只说一句，紧接着退半步，再给一句实在话；
   - 划边界讲道理、不翻脸；
   - 要点赞顺口一句，马上还一点（比如送个小福利），听着不像在讨；
   - 冷场不慌，小声念叨手上正在干嘛；
   - 故事讲到一半问一句“你懂我意思吗”，不等回答接着讲。
4. **肢体层。** 从拼图里挑十来个最有她味道的表情和手势，记当时在干嘛、用在什么场合。常见的发现是：真人动得很少，大部分时间侧着脸看弹幕，手只在讲道理和讲故事时才抬起来。
5. **对到你的动作库。** 已经有的，写清什么时候用；缺的，写成一条精确的新动作描述（手、眼睛、头怎么动，多长时间，怎么收），照第 5 节验收后再上。
6. **建议交给角色自己挑。** 写成她“爱看的直播”一类的笔记，让心自己决定学哪条，不要硬塞成规则。要改代码、改提示的，写成提议；和已经定下的做法冲突的标出来，让负责人决定。
7. **查不到出处的不写进角色。** 网上传的口头禅、刻板印象，找不到原始视频或原话的，一律不用。

**怎么验证**：上线后看记录里有没有出现想学的习惯（比如人多时“先念再答”的比例），同时用 line-lint 确认它没有变成新的重复。

## 8. 常见毛病和修法（速查）

| 症状 | 先看什么 | 常见根子 | 修法 | 怎么确认 |
|---|---|---|---|---|
| 一股 AI 味，换了模型还是一个味 | capture 抓请求 | 外壳塞了几万字、思考模式开着、规矩太长 | 直连、关思考、温度从 1.0 试、短事实页 + 真人示范 | 盲比、人读记录 |
| 动不动声明“我没喊单”“不构成建议” | line-lint `disclaimer` | 心的便签和规则里防备字眼多 | 边界写成她答应过的事，只在真有风险时说 | 次数接近 0 |
| 一个数或词说一晚上 | line-lint `worn` | 心里一直挂着那个话题，示范句偏向它 | `wornTopics` / `wornReply` / `wornNote` | 重放 + 下一场 |
| 开头、结尾、口头禅老一样 | line-lint 重复、开头统计 | 模型抄自己最近的句子 | 最近几句放用户消息末尾；`repeatOf` 重写一次 | 重复比例下降 |
| 英文弹幕用中文回 | line-lint `language` | 全中文提示把模型拉回中文 | `langOf` + 明确只用对方的语言 | 为 0 |
| 接不上刚才的话 | 连续追问测试 | 只带了单条弹幕 | 带最近 10 分钟的对话 | 测试通过 |
| 冷场抱怨没人 | `quiet_complaint`、dead air | 把“没人打字”当成“没人看” | 提示 + 给新素材 | 为 0 |
| 编了又当众收回道歉 | 数“收回”的次数 | 心看不到她刚刷到的原文 | 原文也喂给心；只拦会让人亏钱的 | 次数下降 |
| 群里、推特上的说法和直播相反 | facts-align | 快回通道的小抄没跟上 | 改小抄，加 probe，部署前跑 | align 通过 |
| 心不长进、不记人 | 一周里文件的改动 | 会话重开丢了当天、查错占满每一拍 | 短期记忆文件、下播后固定一拍整理 | 改动数、记人页数 |
| 声音平，“情绪在哪里” | measure、ear | 只给了情绪标签 | 脱口台词 + 分段 + 调音量 + 好参考 | 三项数字 + 盲听 |
| 嘴比声音晚 | 录像对 5 处 | 数字人口型延迟 | 推流里声音延后补偿 | 平均差 < 0.05 秒 |
| 画面一卡一卡 | frame-check fps | 定时器截帧、视频元素在屏幕外 | 来一帧画一帧，帧率一致 | 低窗口为 0 |
| 脸不像 | frame-check sheet | 参考图多套、脸在画面里太小 | 只认一张主脸，裁脸重画 | 并排图逐格看 |
| 一个表情用一晚 | 动作标签统计 | 那一类可选动作太少 | 每类补到三四个 | 占比 < 20% |
| 同一条弹幕回两遍 | 日志里的重复 | 读取时把界面文字读进来 | 去重键 | 为 0 |
| 修好了过两天又坏 | checkup 报告 | 没人每天看 | 每日体检，漏查就补检查项 | 回放那天能报出 |
